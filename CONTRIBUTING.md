# Contributing to Tanikala

Tanikala is an ecosystem of technology products intended to help Filipinos. Keep
changes focused, reviewable, and respectful of the people whose data and trust the
platform handles.

## Before starting

1. Check the repository issues and the Tanikala Roadmap for existing work.
2. Open or claim an issue before beginning a material feature or refactor.
3. Confirm the acceptance criteria and affected application with a maintainer.

## Making a change

- Branch from the current `main` branch using a short descriptive name such as
  `feature/aral-practice-mode` or `fix/upload-validation`.
- Follow the setup and verification commands documented by the repository.
- Include migrations, tests, and documentation when behavior or contracts change.
- Never commit credentials, production data, private reviewer material, or user
  information.
- Keep pull requests limited to one coherent outcome.

## Pull requests

Complete the pull-request template, link the tracking issue, and describe how the
change was verified. A maintainer should review changes before merge even when the
current GitHub plan cannot enforce that policy through protected branches.

Security vulnerabilities and reports containing private data must not be opened as
public issues. Follow `SECURITY.md` instead.
